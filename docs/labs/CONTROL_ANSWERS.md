# 1–4 зертханалық жұмыстың бақылау сұрақтарына жауаптар

Жауаптар кафедра әкімшісінің АРМ-ы және оның SQLModel жабдық каталогы мысалында берілген. Әр зертханалық жұмысқа бес сұрақтан, барлығы 20 жауап қамтылған.

## 1 зертханалық жұмыс

### 1 Виртуал орта не үшін қажет

`venv` әр жобаның Python кітапханаларын бөлек сақтайды. Осы АРМ тәуелділіктері `.venv` ішіне орнатылады және басқа жобалардың нұсқаларына әсер етпейді. Виртуал орта болмаса, бір жоба үшін жаңартылған кітапхана басқа жобаны бұзуы немесе жүйедегі пакеттермен қайшылыққа түсуі мүмкін. Виртуал ортаның өзі тәуелділіктерді толық бекітпейді: оларды қайта орнатуға `requirements.txt` және жоба конфигурациясы қажет.

### 2 gitignore не үшін керек және онда не сақталады

`.gitignore` Git әлі қадағаламайтын файлдардың қайсысын әдеттегі қосу әрекетінде өткізіп жіберетінін анықтайды. `.venv`, кэш, жергілікті SQLite базалары, жүктелген файлдар және құпиясы бар `.env` репозиторийге түспеуі тиіс. Бұл көлемді азайтады және жеке деректердің жариялануына жол бермейді. Бұрын коммиттелген құпияны `.gitignore` өшірмейді: оны тарихтан тазалап, жария болған құпияны ауыстыру керек.

### 3 ИИ бар IDE қандай көмек береді және оның қаупі қандай

VS Code ішіндегі Codex, Cursor немесе басқа ИИ көмекшісі код құрылымын, модельдер мен тест жобаларын дайындауға және қате іздеуге көмектеседі. Ол талапты қате түсінуі, жоқ API-ды қолдануы немесе авторизация мен транзакцияны елемеуі мүмкін. Сондықтан ұсынылған кодты оқу, кітапхана интерфейсімен салыстыру және мінез-құлқын тестілеу қажет. Осы жобада жабдық CRUD-ы бұрыннан бар сессия, рөл және аудит ережелерімен біріктіріледі.

### 4 Git тармағы деген не және main тармағын неге қорғайды

Тармақ — коммиттер тізбегінің белгілі ұшына сілтеме. `git branch` тармақтарды көрсетеді немесе жаңасын жасайды; `git switch -c feature/resources` жаңа тармақ құрып, соған ауыстырады. Бөлек тармақ өзгерісті тексеруге және код ревьюынан өткізуге мүмкіндік береді. `main` тармағына тікелей жазуға тыйым салу — Git-тің міндетті қасиеті емес, команданың қорғалған тармақ саясаты; оның мақсаты тексерілмеген өзгерістен негізгі нұсқаны қорғау.

### 5 commit пен push айырмашылығы қандай

`git commit` дайындалған өзгерістерді жергілікті репозиторийдің `.git` объектілер қоймасына сақтайды. Ол үшін интернет қажет емес. `git push` жергілікті коммиттер мен тармақ сілтемелерін GitHub секілді қашықтағы репозиторийге жібереді. Коммит жасалып, push жасалмаса, өзгерістер тек жергілікті көшірмеде қалады.

## 2 зертханалық жұмыс

### 1 ORM деген не және қандай мәселені шешеді

ORM — реляциялық кестелер мен бағдарлама объектілерін сәйкестендіру тәсілі. SQLModel арқылы `DepartmentResource` класы кестені сипаттайды, ал оның экземпляры жабдық жолын білдіреді. ORM типтерді, объектілерді оқу/сақтауды және байланыстарды бір Python моделінде ұйымдастырады, қайталанатын SQL жұмысын азайтады. Ол SQL, индекстер, шектеулер және транзакциялар туралы білімді алмастырмайды.

### 2 category_id мен category айырмашылығы қандай

`category_id` — жабдық кестесінде сақталатын сандық баған және санат кестесінің алғашқы кілтіне сыртқы кілт. `category` — сол байланысты Python объектісі арқылы пайдалануға арналған `Relationship`. Мысалы, `resource.category.name` санат атауын алуға мүмкіндік береді. `Relationship` үшін бөлек `category` бағаны жасалмайды; дерекқордағы байланыс `category_id` арқылы сақталады.

### 3 Seed не үшін қолданылады

Seed бастапқы анықтамалықтар мен тест деректерін жасайды. Бос базада тізім, сүзгі, байланыс және жаңарту әрекеттерін көрсету қиынырақ. Каталог seed-і 3 санат, 3 бөлме және 4 синтетикалық жабдық енгізеді. Ол бар түгендеу кодтарын қайталамайды және бұрынғы карточкаларды қайта жазбайды. Нақты пайдаланушылардың парольдерін бастапқы демонстрациялық дерек ретінде жариялау қажет емес.

### 4 echo=True не істейді

`create_engine(..., echo=True)` SQLAlchemy орындайтын SQL мен оның параметрлерін логқа шығарады. Бұл кесте құрылуын, INSERT/SELECT сұрауларын және артық қайталанатын сұрауларды көруге көмектеседі. Логта жеке деректер болуы мүмкін және оның көлемі өседі, сондықтан негізгі қолданбада SQL логы әдепкіде өшірулі. Оқшауланған оқу тексерісінде оны уақытша қосуға болады.

### 5 База файлы неге Git-те болмайды, ал модель коды болады

SQLite файлы — өзгеретін орындалу дерегі: онда жеке мәлімет, сессиялар және осы компьютерге тән күй болуы мүмкін. Ол бинарлық файл болғандықтан, жолдық diff пен біріктіру де қолайсыз. Модель, схема құру және seed коды жүйе құрылымын қайталанып жасауға мүмкіндік береді, сондықтан олар репозиторийде сақталады. Таза орнату кодтан жаңа база дайындайды; жұмыс деректерінің резервтік көшірмесі Git-тен бөлек жүргізіледі.

## 3 зертханалық жұмыс

### 1 REST API деген не және GET пен POST айырмасы қандай

REST API ресурстарды URL арқылы таныстырып, олармен HTTP әдістері арқылы жұмыс істеуге мүмкіндік береді. `GET /api/resources` каталогты оқиды және бизнес деректі өзгертпеуі тиіс. `POST /api/resources` жаңа карточка жасайды, JSON денесін қабылдап, сәтті жағдайда 201 қайтарады. POST-ты қайталау әдетте қосымша әрекет тудыруы мүмкін; бұл жобада бірегей түгендеу коды қайталанған карточканы 409 арқылы тоқтатады.

### 2 Pydantic FastAPI ішінде қандай міндет атқарады

Pydantic кіріс деректерін жарияланған типтер мен валидаторлар бойынша тексереді. Каталогта бос атау, теріс сан/құн, бөлшек сан түріндегі `quantity`, артық `id` өрісі және жарамсыз өзгеріс қабылданбайды. Тексеру сәтсіз болса FastAPI 422 қайтарады. Pydantic рөлді немесе объектіге қолжетімділікті өздігінен тексермейді; бұл үшін сервердің авторизациясы және база шектеулері бөлек қажет.

### 3 Depends деген не және ортақ Session неге қауіпті

Dependency Injection функцияға қажет ресурсты фреймворк арқылы береді. `Depends(get_session)` әр сұрауға ORM сессиясын жасап, жұмыс соңында жабады. `Engine` қосылым пулын ортақ пайдалана алады, бірақ өзгеретін `Session` объектісін барлық сұрауға ортақ ету транзакциялар мен объект күйлерін араластырады және қатар орындауға қауіп төндіреді. Бөлек сессияның өмірлік циклі ресурс босатуды және қате кезінде бекітілмеген транзакцияның қайтуын қамтамасыз етеді.

### 4 Swagger құжаттамасы қалай жасалады

FastAPI маршруттар, HTTP әдістері, типтер және Pydantic схемалары негізінде `/openapi.json` спецификациясын жасайды. Swagger UI осы спецификациядан интерактивті бетті құрады, сондықтан әр endpoint үшін HTML қолмен жазылмайды. Бұл жобада кіру cookie-і мен CSRF тәртібін сақтау үшін `/docs` бетінің жүктеу конфигурациясы бейімделген. Дұрыс жергілікті мекенжай — `http://127.0.0.1:8000/docs`.

### 5 422 жауабы нені білдіреді

422 сервер сұрауды алғанын, бірақ оның дерегі маршруттың талаптарына сай келмейтінін білдіреді. Мысалы, `quantity: -1`, бос атау немесе PATCH-та `null` жіберу осындай жауап береді. Клиент деректерді түзетіп қайталауы керек. 404 — объект табылмауы, 401 — жүйеге кірмеу, 403 — рұқсат болмауы, ал 409 — түгендеу коды секілді дерек қайшылығы.

## 4 зертханалық жұмыс

### 1 PUT пен PATCH айырмашылығы қандай

PUT ресурстың толық ұсынылған күйін орнатуға, PATCH оның бір бөлігін өзгертуге арналған. Бір өрісті өзгертуде PATCH аз дерек жібереді: `{"quantity": 3}` қалған өрістерді сақтайды. PUT әдетте идемпотентті; PATCH-тың идемпотенттілігі нақты операциясына байланысты. Осы каталогтың мән тағайындайтын PATCH сұрауын қайта жіберу санды қайта-қайта арттырмайды.

### 2 Query параметрлері қалай беріледі

Query параметрлері URL жолындағы `?` таңбасынан кейін `атау=мән` түрінде жазылып, `&` арқылы бөлінеді. Мысал: `/api/resources?search=компьютер&min_cost=100000&page=1`. Олар осы жобада іздеу, санат/бөлме сүзгісі, құн аралығы және беттеуге қолданылады. URL-ға құпиясөз бен токен салуға болмайды: мекенжай логта және браузер тарихында сақталуы мүмкін.

### 3 PATCH кезінде None мәнінен қалай қорғанады

Жіберілмеген өріс пен ашық жіберілген `null` бірдей емес. `model_dump(exclude_unset=True)` тек жіберілмеген өрістерді алып тастайды; өздігінен `null` мәніне тыйым салмайды. Сондықтан `ResourceUpdate` валидаторы берілген өрістерде `None` болуын және бос `{}` сұрауын қабылдамайды. Жаңа мәндер толық `ResourceCreate` схемасымен де тексеріліп, содан кейін ғана сақталады.

### 4 Жою алдында ID іздеу неге қажет

Алдын ала оқу объектінің бар екенін анықтап, жоқ болса 404 қайтаруға және жойылатын күйді аудитке алуға мүмкіндік береді. Нысанға қатысты қосымша рұқсат пен байланыс тексерістері де осы кезеңде орындалады. Бірақ «алдымен тексеру» өздігінен қатар өзгерту мәселесін шешпейді: тексеру, жою және аудит бір транзакцияда орындалуы керек. Каталогтағы жазу транзакциясы `BEGIN IMMEDIATE` арқылы басталады.

### 5 CRUD нені білдіреді

| Әрекет | Мағынасы | HTTP әдісі | Каталог мысалы |
|---|---|---|---|
| Create | Жасау | POST | Жабдық қосу |
| Read | Оқу | GET | Тізім немесе бір карточка |
| Update | Өзгерту | PUT немесе PATCH | Каталогта PATCH арқылы жеке өрістер |
| Delete | Жою | DELETE | Жабдық жолын физикалық жою |

Жою сәтті болса 204 қайтады. Жазба жойылғаннан кейін сол ID бойынша оқу не өзгерту 404 береді; бұрынғы әрекеттердің аудит тарихы сақталады.
