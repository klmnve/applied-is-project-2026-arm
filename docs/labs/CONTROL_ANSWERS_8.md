# 8 зертханалық жұмыстың бақылау сұрақтарына жауаптар

Орындаған ИС24А-КАЗ тобының студенті **Қалмен Ермек**. Жоба — кафедра әкімшісінің АРМ-ы.

## 1 Интеграциялық тестілеудің негізгі мақсаты қандай

Интеграциялық тест бірнеше компонент бірге жұмыс істегенде олардың келісілген тәртібін тексереді. Мысалы, жабдықты қосу сұрауы HTTP арқылы келіп, сессия мен рөл тексерісінен өтеді, SQLModel арқылы базаға жазылады және аудитпен бірге бекітіледі. Тек жеке функцияның дұрыс жауабы осы тізбектің толық дұрыс екенін дәлелдемейді.

## 2 Unit Testing және Integration Testing айырмашылығы неде

Unit тест шағын логикалық бірлікті тәуелділіктерінен бөліп тексереді; мысалы, сан мен құнның валидаторын. Интеграциялық тест нақты API, авторизация және уақытша SQLite базасының бірге жұмысын тексереді. Жасанды HTTP жауаптары бар Streamlit AppTest интерфейс логикасын бақылайды, бірақ нақты желінің не контейнер DNS-інің жұмысын дәлелдемейді. Әр тесттің шекарасын көрсету қажет.

## 3 REST API тестіндегі HTTP мәртебелері нені білдіреді

200 — операция сәтті; 201 — жаңа ресурс құрылды; 204 — операция сәтті, жауап денесі жоқ. 400 — жарамсыз сұрау; 401 — жарамды аутентификация жоқ; 403 — әрекетке рұқсат жоқ; 404 — ресурс табылмады; 409 — дерек қайшылығы. Бұл FastAPI жобасында кіріс схемасы мен қате JSON валидациясы 422 қайтарады. 500 — сервердің өңдеу қатесі. Тест мәртебемен бірге жауаптың құрылымын және базадағы әсерін де тексеруі тиіс.

## 4 Жүктемелік тестілеудің қандай түрлері бар

Қалыпты load test күтілетін жүктемеде тұрақтылықты өлшейді; stress test жүйенің шегін іздейді; spike test қысқа уақытта күрт өскен сұранысты тексереді; endurance немесе soak test ұзақ орындаудағы ресурстың өсуін бақылайды. Осы зертханалық жұмыста 5, 20, 50 және 100 виртуалды пайдаланушының төрт сценарийі салыстырылады. Бірнеше минуттық нәтиже тәуліктік тұрақтылықтың дәлелі болмайды.

## 5 Response Time және Throughput нені сипаттайды

Response Time — бір сұраудың жауап алу кідірісі, әдетте миллисекундпен беріледі. Орташа мәнмен бірге p95 пайдалы: өлшенген сұраулардың 95%-ы осы уақыттан кешікпей аяқталған. Throughput — уақыт бірлігінде орындалған сұраулар, мысалы request/second. Пайдаланушы саны throughput-пен бірдей емес: күту аралығы, сұраулар қоспасы және сервер кідірісі әсер етеді. Locust кідіріс, throughput және қателерді өлшеп, кейін талдау үшін экспорттайды. [Locust анықтамасы](https://docs.locust.io/en/stable/what-is-locust.html).

## 6 SQL транзакцияларының тұтастығы қалай қамтамасыз етіледі

Транзакция бір логикалық өзгерісті толық бекітеді немесе толық кері қайтарады. ACID атомарлықты, келісілген күйді, оқшаулауды және бекітілген деректің сақталуын сипаттайды. NOT NULL, UNIQUE, CHECK және foreign key шектеулері қате деректің сақталуын тежейді. Осы жобада жабдықты өзгерту мен оның аудиті бір транзакцияда орындалады; аудитке жазу сәтсіз болса, негізгі өзгеріс те сақталмайды. Rollback-тен кейін жолдың күйі және база тұтастығы жеке тексеріледі. [SQLite транзакциялары](https://www.sqlite.org/transactional.html).

## 7 Қауіпсіздік тестілеуінің негізгі міндеттері қандай

Мақсат — кімнің қандай дерекке және әрекетке қол жеткізе алатынын, қате енгізудің өңделуін және құпиялардың қорғалуын тексеру. Осы АРМ үшін бос/әлсіз пароль, қате логин, сессиясыз сұрау, әкімші емес пайдаланушының жазу әрекеті, CSRF, JSON пішімі және қате/log ішінде құпияның көрінуі маңызды. Тесттер тек өзіне тиесілі оқшауланған оқу ортасында синтетикалық аккаунттармен орындалады. Статикалық талдау орындалу кезіндегі рөл мен транзакция тесттерін алмастырмайды.

## 8 pytest не үшін қолданылады

pytest тесттерді табады, орындайды және assertion сәтсіздігінің себебін көрсетеді. Fixture тестке уақытша база, клиент немесе аккаунт дайындайды; параметрлеу бір ережені бірнеше шекаралық мәнмен тексереді. `tmp_path` негізгі файлдарға тимей тест деректерін сақтауға, monkeypatch бақыланатын ақау жасауға көмектеседі. JUnit XML нәтижені CI жүйесінде сақтауға ыңғайлы. [pytest құжаттамасы](https://docs.pytest.org/en/stable/).

## 9 CI/CD жоба сапасына қалай әсер етеді

CI код өзгергенде жинау, стиль, тип және тест тексерістерін бірдей ортада қайталайды. Сәтсіз тексеріс өзгерістің біріктірілуіне дейін қатені байқауға мүмкіндік береді. CD жеткізуге дайындауды немесе автоматты жариялауды ұйымдастырады; тест workflow-ының болуы өндірістік deploy орындалды деген сөз емес. GitHub Actions workflow-ы оқиға арқылы іске қосылып, runner-де job және step-терді орындайды. Осы зертханада негізгі мақсат — сапа тексерісін автоматты іске қосу. [GitHub Actions ұғымдары](https://docs.github.com/en/actions/get-started/understand-github-actions).

## 10 Автоматтандырылған тестілеудің шектеулері қандай

Тест тек таңдалған кірістер мен тексерілетін шарттарды қамтиды. Қате күтімге жазылған тест те «жасыл» болуы мүмкін; жасанды тәуелділік нақты қызметтің ерекшелігін жасырса, интеграциялық қате байқалмайды. Қысқа load test ұзақ memory leak-ті, ал бір компьютердегі өлшеу нақты желі мен өндірістік жүктемені толық сипаттамайды. Сондықтан тест нәтижесі код ревьюымен, нақты браузер/желі тексерісімен және өлшеу ортасының сипаттамасымен бірге бағаланады.

## 11 Жүйе жүктемеге шыдамаса қандай өзгеріс ұсынуға болады

Алдымен ең баяу сұрауларды, SQL жоспарын, блоктауларды, CPU мен жадты өлшеу қажет. Артық сұрауларды қысқарту, индекс пен беттеуді реттеу, ұзақ жұмысты фондық кезекке көшіру көмектесуі мүмкін. Оқу дерегін кэштеу кезінде рөлге тәуелді нәтижелердің араласпауын және ескі құқықпен қолжетімділік қалмауын тексеру керек. SQLite жазу кезегі шекке жетсе, PostgreSQL сияқты серверлік СУБД-ға көшу қарастырылады. Бірнеше worker қосу ортақ SQLite жазу құлпын өздігінен жоймайды; шешім өлшенген себепке сай болуы тиіс.

## 12 Нәтижелерді құжаттау не үшін маңызды

Есеп басқа адамға тестті қайталап, нәтиженің қандай орта мен commit үшін дұрыс екенін түсінуге мүмкіндік береді. Онда сценарий, құрал нұсқасы, пайдаланушылар саны, ұзақтық, мәртебе, жауап, сұраулар саны, қате үлесі және ресурстар көрсетіледі. Шикі JSON/CSV/XML нәтижелері график пен қорытындыны қайта тексеруге мүмкіндік береді. Скриншот көрнекі дәлел береді, бірақ толық лог пен машина оқитын деректі алмастырмайды; пароль мен токен есепке кірмеуі керек.
