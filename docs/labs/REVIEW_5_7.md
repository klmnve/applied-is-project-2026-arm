# 5–7 жұмыстар бойынша кодты тексеру

Тексеру кафедра жабдық каталогының API-ына, Streamlit клиентіне және контейнер конфигурациясына бағытталған. Код ревьюы Codex көмегімен жүргізілді. Төмендегі тұжырымдар қаралған кодқа және аталған тесттерге қатысты; олар жүйеде барлық ықтимал қатенің жоқтығын білдірмейді.

## Backend бойынша тексерілген шешімдер

| Тексерілген жағдай | Кодтағы шешім | Тексеру дәлелі |
|---|---|---|
| Іздеу мәтіні SQL командасына айналмауы | SQLModel `select`/`where`, параметрленген шарттар; `%` және `_` үшін `autoescape=True` | `test_search_combines_filters_pagination_and_escapes_wildcards` |
| Жарамсыз POST/PATCH жазбаны өзгертпеуі | Бөлек кіріс схемалары, артық өріске тыйым, сан/құн шектеуі; PATCH-та бос өзгеріс пен `null` қабылданбайды | `test_invalid_create_is_rejected_without_side_effects`, `test_invalid_partial_update` |
| Рұқсатты интерфейс арқылы айналып өтпеу | Backend-та permission және нақты әкімші рөлі тексеріледі; рөл транзакция ішінде қайта оқылады | `test_authentication_csrf_and_actual_admin_required` |
| Басқа сайттан жасалған өзгерту сұрауы | Сессия cookie-і, `X-CSRF-Token`, cookie және сервердегі хэш салыстырылады | Сол авторизация/CSRF тесті |
| Аудит сақталмаса бизнес өзгеріс бекітілмеуі | Жабдық өзгерісі және `Store.audit` бір қосылымда, бір транзакцияда; commit соңында | `test_business_change_rolls_back_when_audit_fails` — create/update/delete |
| Жоқ және қайталанған объектілер | Жоқ ID — 404, қайталанған түгендеу коды — 409, жоқ FK — 422 | `test_duplicate_missing_foreign_keys_and_missing_ids` |
| Seed жойылған жазбаны қайта тудырмауы | Бір рет seed орындалғанын сақтайтын белгі | `test_relationships_one_time_seed_and_existing_data_preservation` |

Осы шешімдер `app/routers/resources.py`, `app/database/models.py`, `app/database/db.py`, `app/database/seed.py` және қолданыстағы `app/auth.py` кодынан тексерілді. Нақты серверлік сессия мен CSRF логикасын өшіру қажет емес.

## Streamlit бойынша тексерілген шешімдер

`app/frontend/client.py` және `ui.py` кодында HTTP клиенті `st.session_state` ішінде әр сессияға бөлек жасалады; ортақ cookie кэші жоқ. Өзгерту сұраулары CSRF тақырыбын қосады. Timeout `(5, 20)` және `allow_redirects=False` қойылған. Көлік қатесінің ішкі мәтіні пайдаланушыға берілмейді; 5xx жауабына жалпы хабар көрсетіледі.

Logout және 401 жауабы cookie мен интерфейс күйін тазартады. Сервер қолжетімсіз logout кезінде клиент жергілікті кіруді тоқтатып, сервер сессиясын тоқтату расталмағанын нақты хабарлайды. Әр әрекетте `/api/auth/me` арқылы құқықтар қайта оқылады; интерфейс түпкілікті серверлік рұқсат тексерісін алмастырмайды.

Өңдеу формасының ескі күйі сақталып қалмауы үшін сәтті өзгерістен кейін және «Жаңарту» басылғанда snapshot пен өріс күйі тазаланады. Жою нысанын A→B→A ауыстырғанда бұрынғы растау қайта қолданылмайды. Бұл екі шекаралық жағдай `test_ui_refresh_discards_stale_editor_snapshot` және `test_ui_switching_delete_target_requires_fresh_confirmation` тесттерімен қамтылған. Қалған AppTest сценарийлері кіру/шығуды, CRUD-ты, іздеуді, қате парольді, бос форманы, offline күйін, сессия мерзімін, құқықтың өзгерісін және екі браузер сессиясының оқшаулығын тексереді.

Нақты браузердегі сынақ жоюды растаудан кейін белсенді қойындының ауысуын анықтады. Басқару қойындыларына тұрақты `management_tab` кілті және `on_change="rerun"` берілді. `test_ui_delete_tab_stays_selected_after_confirmation_rerun` регрессиялық тесті қосылды; толық браузер сценарийінде DELETE 204 және одан кейінгі GET 404 расталды. Streamlit/HTTP клиентінің 11 тесті және браузердегі толық CRUD сценарийі өтті.

## Контейнер конфигурациясын тексеру

Екі Dockerfile тәуелділіктерді кодтан бұрын көшіреді және root емес пайдаланушымен орындалады. `.dockerignore` тек қажетті код пен конфигурацияны өткізетін тізімді қолданады; жергілікті база, `.env`, `.venv`, модельдер және Git тарихы build контекстіне кірмейді. Compose порттарды `127.0.0.1` адресіне жариялайды, `no-new-privileges` және `cap_drop: ALL` қояды. Frontend ішкі `backend` сервис атауын қолданады және оның healthcheck нәтижесін күтеді. SQLite мен uploads `arm_data` volume-ында орналасқан.

`scripts/docker_smoke.py` кездейсоқ атпен жеке Compose жобасын құрады. Ол нақты HTTP арқылы авторизация, CSRF, CRUD, валидация, DNS, root емес пайдаланушы және `down`/`up` арасындағы база мен файлдың сақталуын тексереді. Тазалау тек сол уақытша жобаның volume-ына қатысты. Бұл сценарий 2026 жылғы 12 қарашада [GitHub Actions Linux тапсырмасында өтті](https://github.com/klmnve/applied-is-project-2026-arm/actions/runs/43167035722/job/131011187469); `artifacts/lab5-7/final-ci/docker/smoke-result.json` нәтижесі — `passed`. Негізгі жұмыс дерекқоры қолданылмады.

## Толық регрессиялық тексеру

Алғашқы толық тексеріс студенттің ескі өтінімін тексеретін екі тесттегі сәйкессіздікті көрсетті: тест дерегі оқытушы ретінде тіркеліп, студент ретінде мақұлдануға жіберілген. `legacy_student_request` көмекшісі бұрынғы `StudentClaims` жазбасы жоқ, нақты студент өтінімін жасайтын болып түзетілді. Backend-тің оқытушы рөлін шектеуі және тесттердегі күтілетін нәтижелер өзгерген жоқ. Осы екі тест пен рөлді тексеретін бес қосымша сценарий жергілікті ортада өтті. Соңғы CI-де барлық **609 тест**, Ruff, формат, MyPy, нақты браузер және Docker тексерістері сәтті аяқталды.

## Тексеру шегі

Streamlit серверден серверге HTTP клиенті болғандықтан, backend аудитіндегі IP Streamlit серверінің/контейнерінің адресі болады. Клиент браузерінің IP-ін ойдан `X-Forwarded-For` арқылы жіберу енгізілмеген. AppTest жасанды HTTP жауаптарын қолданады; нақты желі мен контейнерлер бөлек тексеріледі. Осы Windows компьютерінде Docker/WSL жоқ, сондықтан Docker орындалуы қашықтағы Linux ортасында расталды. Автотесттің соңғы нәтижелері [орындау есебінде](REPORT_5_7.md) көрсетілген.
