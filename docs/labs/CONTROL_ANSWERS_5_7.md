# 5–7 зертханалық жұмыстың бақылау сұрақтарына жауаптар

Жауаптар кафедра әкімшісінің АРМ-ы және оның жабдық каталогына бейімделген. Барлығы 15 сұрақ: әр жұмысқа бесеуден. Әдістемедегі орындары ауысқан екі Streamlit сұрағы 5 жұмысқа, тестілеу туралы бес сұрақ 7 жұмысқа енгізілді.

## 5 зертханалық жұмыс

### 1 Streamlit пен FastAPI қалай байланысады

Браузер Streamlit бетімен жұмыс істейді, ал Streamlit серверіндегі Python коды `requests` арқылы FastAPI-ға HTTP сұрауларын жібереді. Каталогты оқу — GET, қосу — POST, өзгерту — PATCH, жою — DELETE. Сүзгілер URL параметрлерінде, жазбаның өрістері JSON денесінде беріледі. Backend авторизацияны, деректерді және база шектеулерін тексеріп, JSON жауап пен HTTP мәртебесін қайтарады. Streamlit базаны тікелей ашпайды.

### 2 requests не істейді және params пен json айырмасы қандай

`requests` — Python-нан HTTP сұрауларын жіберетін кітапхана. `params={"search": "компьютер"}` URL query жолын құрып, мәндерді дұрыс кодтайды. `json={"quantity": 3}` сұрау денесін JSON ретінде жіберіп, тиісті мазмұн түрін белгілейді. Осы жобада `requests.Session` кіруден алынған cookie-лерді сақтайды; өзгерту сұрауларына CSRF тақырыбы қосылады. [Requests анықтамасы](https://requests.readthedocs.io/en/latest/user/quickstart/).

### 3 Backend өшсе интерфейсте не болады

Streamlit сервері жұмысын жалғастыруы мүмкін, бірақ API-дан жаңа дерек ала алмайды. Қосылым орнамаса `ConnectionError`, жауап белгіленген уақытта келмесе `Timeout` туындайды; сервердің 500 жауабы бұлардан бөлек жағдай. Клиент осы қателерді ұстап, түсінікті хабар көрсетуі тиіс. Сәтсіз POST-тан кейін «сақталды» деп көрсетуге немесе жазу сұрауын автоматты қайталай беруге болмайды: жауап жоғалса да сервер өзгерісті сақтап үлгеруі мүмкін. [Қателер және timeout](https://requests.readthedocs.io/en/latest/user/quickstart/#errors-and-exceptions).

### 4 Streamlit скриптті неге қайта орындайды

Әдепкі орындау моделінде виджет мәні өзгерген соң сессия күйі жаңарып, callback болса орындалады, кейін скрипт жоғарыдан төмен қайта орындалады. Осылайша Python коды жаңа мәндерден экранды қайта есептейді. Қажетті күй `st.session_state` ішінде сақталады. `st.form` өрістерін бір жіберуге біріктіреді, ал fragment тек тиісті бөлікті қайта орындай алады; сондықтан «кез келген әрекет әрқашан толық скриптті іске қосады» деген тұжырым дәл емес. [Streamlit орындау моделі](https://docs.streamlit.io/develop/concepts/architecture/session-state).

### 5 Streamlit артықшылығы мен шектеуі қандай

Дайын Python виджеттері кесте, сүзгі және форма құруды жылдамдатады; бөлек JavaScript клиентін әзірлемей-ақ оқу және ішкі жұмыс құралын жасауға ыңғайлы. Бірақ интерфейс мінез-құлқы мен орналасуын еркін басқару классикалық HTML/CSS/JavaScript қолданбасына қарағанда шектеулі. Қайта орындау моделінде артық API сұрауларын, ұзақ операцияларды және сессия күйін ескеру керек. Осы АРМ-да Streamlit жабдық каталогының қосымша клиенті, ал негізгі көпбөлімді интерфейс бөлек сақталған.

## 6 зертханалық жұмыс

### 1 Контейнер мен виртуалды машина айырмасы қандай

Контейнер қолданбаны оның кітапханаларымен және файлдық ортасымен іске қосады, бірақ өзі орындалатын жүйенің ядросын ортақ пайдаланады. Классикалық виртуалды машина жеке қонақ операциялық жүйені және оның ядросын іске қосады. Контейнер әдетте жеңілірек және тез іске қосылады. Windows-та Linux контейнерлерін Docker Desktop WSL 2 немесе виртуал машинадағы Linux ядросы арқылы іске қосуы мүмкін; бұл контейнердің ішінде толық жеке ОС бар деген сөз емес.

### 2 Dockerfile нұсқаулары не істейді

`WORKDIR` келесі командалар мен бағдарламаға жұмыс каталогын белгілейді. `COPY` файлдарды build контекстінен image ішіне көшіреді. `EXPOSE` қолданба тыңдайтын портты сипаттайды, бірақ оны хостқа өздігінен жарияламайды; ол үшін Compose `ports` қолданылады. `RUN` image құрастырылған кезде орындалады, мысалы тәуелділіктерді орнатады. `CMD` контейнер іске қосылғандағы әдепкі команданы береді, мысалы Uvicorn немесе Streamlit. [Dockerfile анықтамасы](https://docs.docker.com/reference/dockerfile/).

### 3 dockerignore не үшін қажет

`.dockerignore` build контекстінен қажетсіз және жеке файлдарды алып тастайды. Бұл жобада `.venv`, кэш, жергілікті дерекқорлар, `.env`, Git тарихы және тексеру артефактілері image-ке көшірілмеуі тиіс. Windows-та жасалған `.venv` Linux image-іне жарамауы мүмкін, image көлемін өсіреді және image ішінде орнатылған пакеттермен шатастырады. Тәуелділіктер контейнердің өз Python ортасына requirements файлдарынан орнатылады. [Docker build контексті](https://docs.docker.com/build/building/context/#dockerignore-files).

### 4 backend атауы қалай IP мекенжайға айналады

Compose сервистерді ортақ желіге қосады. Docker-дің ішкі DNS қызметі `backend` сервис атауын сол желідегі контейнердің IP мекенжайына сәйкестендіреді. Сондықтан frontend контейнеріндегі `BACKEND_URL=http://backend:8000` дұрыс жұмыс істейді; `localhost` сол frontend контейнерінің өзін білдірер еді. Браузерде хостқа жарияланған `http://localhost:8000` қолданылады. Контейнер қайта жасалғанда IP өзгеруі мүмкін, ал сервис атауы тұрақты қалады. [Compose желісі](https://docs.docker.com/compose/how-tos/networking/).

### 5 docker compose down дерекқорға қалай әсер етеді

Егер SQLite файлы тек контейнердің жазылатын қабатында болса, контейнер жойылғанда ол да жоғалады. Базаны атауы бар volume-ға орналастыру деректерді контейнердің өмірлік циклінен бөледі. Әдеттегі `docker compose down` named volume-ды өшірмейді; келесі іске қосу сол деректі қайта пайдаланады. `down --volumes` volume-дарды да жояды, сондықтан жұмыс дерегі бар кезде бұл параметрді қолданбау керек. Volume резервтік көшірмені алмастырмайды. [Compose down анықтамасы](https://docs.docker.com/reference/cli/docker/compose/down/).

## 7 зертханалық жұмыс

### 1 Автоматты тест не үшін қажет

Unit тест жеке функцияның логикасын, интеграциялық тест бірнеше қабаттың бірге жұмысын тексереді. API тесті сұрауды өңдеуді, авторизацияны, валидацияны және базаға әсерін қайталанатын түрде тексере алады. Қолмен Swagger-де әр өзгерістен кейін ондаған қате мен рөл сценарийін қайталау баяу және кей жағдайды өткізіп алу оңай. Қолмен тексеру интерфейс ыңғайлылығына пайдалы, автоматты тест нақты ережелердің сақталуын бақылайды.

### 2 TestClient үшін Uvicorn іске қосу қажет пе

`fastapi.testclient.TestClient` FastAPI қолданбасына тест процесінің ішінде сұрау жібереді. Бөлек Uvicorn процесі мен бос TCP порты қажет емес. `with TestClient(app) as client:` контексті қолданбаның lifespan іске қосу/тоқтату кезеңдерін де орындайды. Клиент HTTP жауабын, JSON және cookie-лерді тексеруге мүмкіндік береді. Нақты желі, контейнер немесе браузер әрекеті бөлек интеграциялық тексеріспен расталады. [FastAPI тестілеу нұсқаулығы](https://fastapi.tiangolo.com/tutorial/testing/).

### 3 httpx қандай рөл атқарады

HTTPX HTTP клиентін береді және Starlette/FastAPI TestClient негізінде қолданылады. Асинхронды тестте `httpx.AsyncClient` пен `ASGITransport` арқылы `await` қолданып API-ды тексеруге болады. Бұл әсіресе тест ішінде асинхронды база функцияларын да шақырғанда ыңғайлы. ASGITransport қолданғанда lifespan іске қосылуын бөлек қамтамасыз ету қажет. Қазіргі синхронды каталог тесттеріне кәдімгі TestClient жеткілікті. [FastAPI асинхронды тесттері](https://fastapi.tiangolo.com/advanced/async-tests/).

### 4 ИИ код ревьюына қалай көмектеседі

ИИ бірнеше файлдағы байланысты тез салыстырып, қате өңдеуі, SQL сұрауы, рөл тексерісі және транзакция шекарасы бойынша тексеру сценарийлерін ұсынады. Осы жұмыста Codex қолданылды. Ұсыныстың дұрыстығы бастапқы кодпен және тестпен расталуы керек: ИИ маңызды қатені өткізіп алуы немесе жоқ мәселені көрсетуі мүмкін. «ИИ қарап шықты» деген тұжырым қауіпсіздік кепілдігі болмайды.

### 5 Регрессиялық тестілеу деген не

Регрессиялық тест жаңа өзгерістен кейін бұрын дұрыс жұмыс істеген мінез-құлықтың сақталғанын тексереді. Мысалы, Streamlit қосылғаннан кейін авторизацияны айналып өтуге болмайды, жарамсыз POST базаға жазылмауы керек, PATCH басқа өрістерді сақтауы және аудит қатесі кезінде өзгеріс қайтарылуы тиіс. Осындай тесттер кейінгі өзгеріс ережені бұзса, оны жеткізуге дейін байқатады. Тесттер тек қамтылған сценарийлерді растайды, барлық ықтимал қатенің жоқтығын дәлелдемейді.
